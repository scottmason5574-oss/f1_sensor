# F1 Sensor repository audit

The actual fork checkout was inspected at `58272f07e57c98b56a719c6042912df8e9f6841f`. Both default branches were main and their symmetric difference was 0/0. The earlier snapshot identifies this same SHA. The findings below refer to Git source; timing behavior still needs replay and live validation.

Backend paths below are relative to `custom_components/f1_sensor/`. Frontend paths are under `custom_components/f1_sensor/www/f1-sensor-live-data-card/modular/`.

| Subsystem | Source and interfaces | Clock, history and mode implications | Circle work |
| --- | --- | --- | --- |
| Physical map | Backend track_map.py has TrackMapStore and TrackMapReplayAdapter. track_map_websocket.py serves snapshots, resync and subscriptions. Frontend TrackMapState and mapModel in map-data.js handle snapshots, projection and driver metadata. map-view.js renders the map; map-geometry.js displayTrack handles geometry smoothing. | Map samples and replay interpolation belong to spatial position. mapFreshness/mapExpiry address map freshness; they do not establish gap freshness. Replay adapter builds physical interpolation from replay samples. | Preserve physical transport and renderer. Reuse metadata and lifecycle conventions. A timing-only circle must render without position samples or track geometry. |
| Timing and gaps | TimingData drives timing state. card.js consumes driver_positions, and catalog.js TIMING_FIELDS declares display fields. analysis.py consumes GapToLeader and related timing state. | Gaps and intervals are display-oriented and can carry nonnumeric states. Entity update time can differ from source event time. Current values alone cannot reconstruct previous gaps or prove lap deficits. | Validate gap sign, anchor, format and lap offset with fixtures; do not coerce lap tokens, absent or stale values to zero. |
| Lap and sector | TimingData and driver_positions supply current/latest lap and sector values. Phase4AnalysisStore._capture_strategy_laps accumulates per-driver lap observations for analysis. | A strategy lap sample and a complete ordered crossing history are separate interfaces. Corrections and completion-time availability need verification. | First assess whether existing lap observations support a reference median; expose only missing completion times, validity and status context. |
| Minisectors | MiniSectorStateStore in minisectors.py, minisector_websocket.py and minisector-data.js support bounded status frames; see the [contract](https://github.com/scottmason5574-oss/f1_sensor/blob/ee2f621ff3cd5a5937ea59df9991c07746d2edd7/quality/minisector-contract.md). | Sparse segment updates merge within a source/session generation. Archive fixtures lack per-segment times. Replay status playback is not evidence of crossing timestamps. | Defer crossing-based reference and interpolation until a feed or validated inference supplies crossing events with explicit uncertainty. |
| Stops and tyres | sensor.py F1PitStopsSensor, F1CurrentTyresSensor and F1TyreStatisticsSensor expose stops and compound/stint context. Phase4AnalysisStore._on_pit_stops and TimingAppData handling feed analysis. | A stop observation, stationary duration, pit-lane duration and in/out-lap race loss have different semantics. Verify replay coverage and as-of joins before aggregating. | Reuse recorded observations where available; add only missing lap associations, completion/availability timestamps or quality flags. |
| Strategy and battle history | analysis.py UnifiedTimelineStore and Phase4AnalysisStore; analysis_websocket.py; frontend analysis-data.js timelineModel, battlesModel and strategyModel. | Analysis uses TimingData, TimingAppData and TrackStatus plus other inputs to produce timeline, battle and strategy views. Existing analysis snapshots are not an established synchronous hypothetical rejoin contract. | Reuse upstream observations and avoid a separate ingest pipeline. Build one pure prediction engine with an as-of input. |
| Track status | TrackStatus is routed into analysis.py and integration status handling. | A current status can select a scenario; a lap or stop spanning a transition needs ordered status events over the whole interval. Replay source must match the timing source. | Validate timeline coverage; classify incomplete or mixed intervals conservatively and suppress red-flag predictions initially. |
| Live Delay | live_delay.py LiveDelayController and delay routing around consumers. | The contract must align released events across topics. Wall-clock freshness and source-event alignment are distinct. Delayed analysis has regression coverage. | Use the existing delay boundary. Add no independent browser delay. Verify reconnect warm-up and delay changes across all inputs. |
| Replay | replay.py ReplayFrame and ReplaySignalRClient, replay_mode.py, TrackMapReplayAdapter and card.js playback plumbing. | Archive events have a playback timeline. Seeking can rebuild state and invalidate animations; speed scales presentation. Replay history availability depends on archive coverage. | Ensure no future observations at seek target and clear model state on source/session changes. Verify cold seek versus linear playback. |
| Selection and configuration | card.js focus control and mapModel inputs; catalog.js MODULES and field definitions. | Focus can be shared across modules; saved/frozen card state has a separate generation context. | Reuse focused driver and card configuration. Add validated display mode and editor support without altering old defaults. |
